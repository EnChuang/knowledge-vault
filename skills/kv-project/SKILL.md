# kv-project — Project 筆記

Canon：`Project_rules.md`。前置：AGENTS 啟動前置；寫入前須有 MOC（或同次建最小 MOC）。**例外**：庫根 `工具/配色查詢表.md` → **kv-palette**（§13；不屬 Project）。

## Overview

Project 筆記體裁：科普掃讀／Ebook §12、自測、標籤。  
Canon：`Project_rules.md`。
方針：全庫統一的只有定位（Overview）＋少數硬閘／步驟方向；其餘表述、舉例、臨場策略不制式化，容許容錯與自由發揮。設計型若要鎖風格，再個別補 Reference，不上升成全庫義務。

## Agent 使用步驟

1. 判定非 Ebook vs Ebook §12。
2. 整理時含 30 秒／分鏡／收束（非 Ebook）；一般知識筆記做讀者自測，使用指南類文件改做 FAQ／操作覆蓋複核。
3. 請寫入走 kv-flow；連動 MOC。

| 類型 | 體裁 |
|------|------|

### 科普掃讀（非 Ebook）

讀者只讀此檔掌握約 **80%**；像**投影片＋知識貼文**，可掃可滑。

| 目標 | 要求 |
|------|------|
| 自足 | 跨篇只在開頭／結尾 |
| **可掃讀** | 分鏡標題；短句；表／步驟優先 |
| 可滑完 | 單段宜 ≤4 行；禁長文牆 |
| 去噪 | 無導流 |

**骨架**：一句命題 → **本篇 30 秒**（3–5 條）→ 為什麼要懂（短）→ 分鏡展開（表卡為主、卡點一句譬喻）→ **記住這 N 點** → 延伸 → **自測或重讀校正清單**（指南類改為 FAQ／操作檢查表；見 §3）。

**大眾心理／科普式標題**（Canon：[[Project_rules]] §2；自由整理葉預設）

- 檔名與 `##` 像大眾心理學／科普章名：**一眼懂在講什麼**  
- **內容標題須完整句子**（例：✅可以預想最壞的情境，但不要是連播災難片）  
- **禁標題括號後設注釋**（❌不是診斷；免責寫節內正文）  
- **葉標題＝蒸餾命題**（尤以影音／對談）：先蒸一句主主張再當檔名；❌`節目 · ft. 來賓`／`（博音 EP233）`；✅`很會抗壓，不代表壓力有被處理`、`不知道自己的價值，困境就容易長出來`；原標題只放正文引用  
- **命名前先讀正文**：先寫出「主體＋核心主張＋兩者關係」，不得只看舊名或摘要重組詞語  
- **準確先於金句感**：隱喻預設留正文；若標題需先解釋譬喻才看得懂，或把兩個無明確關係的意象拼在一起，就必須改回具體直白的名稱  
- 影音大綱＝完整句列表，不寫時間、不寫「不記時間」等後設句  
- 節首可白話「這一節只做什麼」；表可加「接著怎麼辦」  
- **不重寫大綱**：Ebook §12、教科書／傳記固定章序、MOC 已定型版型；功能段短名可保留  

**寫作前四問**（非例外檔）：

1. 有「30 秒帶走」嗎？  
2. 滑過**大綱標題**能抓架構嗎？每條是否**完整句**？  
3. 卡點有一句譬喻嗎？  
4. 收束 3 點清楚嗎？  

**中英術語完整**（Canon：[[Project_rules]]）：中文語意完整可獨立讀懂；禁因英譯半截詞（例：錨點≠錨）；首次可附英文，之後用完整中文；標題寫內容本身、禁後設講解腔。**給人讀的文案更嚴**。

用戶明示「長文／論述」該次可改走段落敘事。

## §3 讀者自測／覆蓋複核

**使用指南類文件例外**：若文件定位是使用指南、操作指南、快速開始、開箱導覽、FAQ 或疑難排解，不寫讀者自測；改用 `## 常見問題`、`## 疑難排解`、`## 操作檢查表` 做主流程、分支、失敗訊號、限制與下一步的覆蓋複核。一般知識筆記與 Ebook 不受此例外影響。

**預設（多數專題）**

1. **8–12 題**（緊扣核心）；Ebook §12 → **10 題**  
2. 僅讀正文作答  
3. 答不出 → 補正文 → 重測；Ebook → 10/10  
4. 答案可寫入 `<details>` 或「讀者自測答案」區  

**例外：`Project/認知科學/`**（Canon：[[Project_rules]] §3）

1. **禁止**考卷式藏答案自測  
2. 必有 **`## 重讀校正清單`**（5–8 條）：問句／觀察＋**同屏指引**  
3. 寫入前複核：清單能否校正核心誤讀；不能 → 補正文  
4. 簡報報清單條數，不報考卷題數  
5. Ebook §12 **不**適用本例外  

## §4 命名

檔名＝`title`＝wikilink。禁 `討論`、`草稿`、純日期。Ebook：`{章號} · {章標題}.md`。命名前須讀正文，確認標題能直接表達主體、核心主張與概念關係；質感不得以語意含混交換。

## §5 卡點譬喻

卡點一句譬喻 → 一句收斂；全文至少 1 則（非 Ebook）。

## §8–§9

分段：未請寫入只草稿。標籤無空格：`AI/Harness`。

## §12 Ebook 蒸餾（預設）

**`Source/Ebook/` 且用戶未另指定 → 必用。不套科普骨架。**
